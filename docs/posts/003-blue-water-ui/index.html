BLUE WATER 水下的界面：为什么 P3R 的蓝是对的

2026.09.12·2 min·你的代号·设计

《女神异闻录3 Reload》的主创在访谈里说得很直白：整套 UI 的概念是「蓝色与水」，菜单是主角深层心理的投射，交互逻辑是沉进自己的内心深处，去确认与他人的关系和信息。

于是一切视觉决策都有了出处。

三个可以立刻用的手法#

一、把光源放在画面之外#

水下照片的共性是：你能看见光，但看不见灯。P3R 的界面把这条搬了过来——所有高亮都是从面板边缘漏进来的，而不是从中心打出去的。

做法：

.panel::before {
  /* 光从上方斜切面漏下来，而不是均匀铺满 */
  content: '';
  position: absolute;
  inset: -20% -10% auto;
  height: 120vh;
  background: repeating-linear-gradient(78deg,
    transparent 0 62px, var(--sea-1) 62px 66px);
  mask-image: linear-gradient(180deg, rgba(0,0,0,.85), transparent 78%);
}

关键是 mask-image：光必须有衰减，不然它只是条纹背景。

二、动效要有阻力#

水的物理特性是黏滞。所以界面元素不该用 ease-in-out，而该用一条起步快、尾巴长的曲线：

transition: transform .42s cubic-bezier(.2, .8, .2, 1);

同一套缓动用在 hover 位移、面板展开、页面转场上，整个界面就会有一种「所有人都在同一种液体里」的统一感。反之，一个按钮用 spring、一个卡片用 linear，那种廉价感是无法解释的。

三、把环境动画的帧率压到 30#

呼吸感来自慢。焦散、气泡、光柱这些背景元素，60fps 反而显得躁。用 requestAnimationFrame 手动限帧，比降缓动幅度更能提升「质感」。

一个反例：为什么它不适合后台系统#

P3R 的这套语言有三个前提：内容稀少、情绪重要、用户愿意慢下来。

后台系统三个都不满足。所以「蓝色与水」搬到管理端，就变成了加载动画过长、对比度不足、信息密度太低。

抄风格之前先核对前提。前提不一致，抄来的只会是负担。

我在这个博客里做了什么#

  • 背景是三层：radial-gradient 的压强梯度 + 斜切光柱 + canvas 的焦散与气泡；
  • 顶栏与卡片的 hover 都走同一条缓动；
  • canvas 限帧 30fps，prefers-reduced-motion 下直接不启动；
  • 唯一的高饱和色是 --accent，它同时决定月相、进度条、链接下划线的颜色，换主题时整套色温一起变。

代价是：文字对比度我必须一直盯着。冷底上放低饱和浅蓝，很容易好看得看不清——这也是这类「氛围优先」界面最常见的死法。
